## 📖 I. ЧТО ЭТО

**Ettercap** — классический инструмент для атак **Man-in-the-Middle** в локальной сети. Работает на уровне L2 (ARP). Умеет:
- ARP-спуфинг (перенаправление трафика через себя).
- Сниффинг паролей (HTTP, FTP, Telnet, POP, IMAP).
- Подмену данных на лету (фильтры).
- DNS-спуфинг (через плагины).

**Отличие от [[bettercap]]:**
| | Ettercap | Bettercap |
|---|---|---|
| Язык | C | Go |
| GUI | Есть (старый) | Нет (консоль) |
| Модули | Плагины | Встроенные модули |
| Скорость | Медленнее | Быстрее |
| Актуальность | Устаревает | Активно развивается |

> [!tip] Совет Легиона
> Изучай Ettercap для понимания классического MITM, но в реальных атаках используй [[bettercap]]. Ettercap — это история, Bettercap — современность.

## 🚀 II. ПОДГОТОВКА

### Шаг 1: Включить пересылку пакетов

> [!warning] Критично
> Без этого жертва потеряет интернет и MITM не сработает.

```bash
# Проверить текущее значение
cat /proc/sys/net/ipv4/ip_forward
```

- `1` — уже включено, ничего менять не надо.
- `0` — выключено, включаем:

```bash
echo 1 > /proc/sys/net/ipv4/ip_forward
```

> [!info] Что это даёт
> Пакеты жертвы будут проходить через твою Kali и уходить дальше в интернет. Без этого они просто умрут на твоей машине, и жертва мгновенно заметит проблему.

### Шаг 2: Запустить Ettercap (GUI)

```bash
sudo ettercap -G
```

Откроется графическое окно Ettercap.

## 🎯 III. АТАКА: ARP-SPOOFING (GUI)

### Шаг 1: Обнаружение хостов

1. В верхнем меню нажми **значок лупы** (🔍) — «Scan for hosts».
2. Ettercap начнёт ARP-сканирование сети.
3. Через 10–20 секунд нажми **значок списка** рядом с лупой — «Hosts list».

**Что увидишь:** список всех устройств в сети с IP и MAC.

> [!example] Пример
> ```
> 192.168.56.1    08:00:27:xx:xx:xx   (шлюз)
> 192.168.56.20   08:00:27:yy:yy:yy   (Ubuntu)
> 192.168.56.30   08:00:27:zz:zz:zz   (Windows 10)
> 192.168.56.50   08:00:27:aa:bb:cc   (Metasploitable)
> ```

### Шаг 2: Выбор целей

**Классический MITM требует двух целей:**
- **Target 1** — жертва (например, `192.168.56.30` — Windows).
- **Target 2** — шлюз (например, `192.168.56.1`).

1. В списке хостов выбери **жертву** → **Add to Target 1**.
2. Выбери **шлюз** → **Add to Target 2**.

> [!warning] Почему два таргета?
> Ты становишься «посредником» между жертвой и шлюзом. Жертва думает, что ты — шлюз. Шлюз думает, что ты — жертва. Весь трафик идёт через тебя.

### Шаг 3: Запуск ARP-отравления

1. В меню **Mitm** выбери **ARP poisoning**.
2. Поставь галочки:
   - [x] **Sniff remote connections** — перехватывать трафик.
   - [x] **Only poison one-way** — оставь выключенным (нужна двусторонняя атака).
3. Нажми **OK**.

**Ettercap начнёт отравлять ARP-таблицы.** В нижнем окне появится лог атаки.

### Шаг 4: Просмотр трафика

1. В меню **View** → **Connections** — увидишь все соединения.
2. Вкладка **Credentials** — пароли, перехваченные в открытом виде (HTTP, FTP, Telnet).
3. Вкладка **Packets** — сырой трафик.

> [!danger] Реальность
> HTTPS-трафик через Ettercap **не виден** — он зашифрован. Для HTTPS нужен [[bettercap]] с sslstrip или mitmproxy.

## 🛠️ IV. ОСТАНОВКА АТАКИ

> [!warning] Обязательно
> Перед завершением нужно **восстановить ARP-таблицы**, иначе жертва останется без интернета.

1. В меню **Mitm** → **Stop mitm attack(s)**.
2. Ettercap автоматически вернёт ARP-таблицы в норму.
3. Закрой Ettercap (`Ctrl+Q`).

Если что-то пошло не так и жертва потеряла интернет:
```bash
echo 0 > /proc/sys/net/ipv4/ip_forward
```
Затем перезагрузи жертву — ARP-таблица восстановится.

## 🛡️ V. ДЕТЕКТ В WAZUH

> [!danger] MITRE
> - **T1557.002** — ARP Cache Poisoning
> - **T1040** — Network Sniffing

### Что видно защитнику

| Источник | Что искать |
|---|---|
| **Suricata** | ARP-аномалии, дублирование MAC |
| **Zeek** | ARP-спуфинг (правило `ARP_Spoofing`) |
| **Wazuh Agent** | Изменение ARP-таблицы на хосте |
| **Switch / Router** | MAC-flapping, дублирующиеся IP |
| **arpwatch / arpalert** | Уведомления о смене MAC |

### Практика в лабе

1. На **Ubuntu-жертве** запусти мониторинг ARP:
   ```bash
   watch -n 1 arp -a
   ```
2. С **Kali** запусти ARP-спуфинг через Ettercap.
3. На Ubuntu **MAC-адрес шлюза изменится** на MAC Kali.
4. Это и есть сигнал атаки.

### Пример лога Wazuh

```
Rule: 5104 (level 6) -> 'Host scan detected'
Src IP: 192.168.56.107
Dst IP: 192.168.56.30
MITRE: T1557.002
```

> [!info] Как защититься
> - **Dynamic ARP Inspection (DAI)** на коммутаторах.
> - **Статические ARP-записи** для критичных узлов.
> - **802.1X** — авторизация устройств в сети.
> - **Мониторинг ARP** через Suricata / Zeek.

## 🩺 VI. ТРОУБЛШУТИНГ

| Проблема | Решение |
|---|---|
| Жертва потеряла интернет | Включи `ip_forward` до атаки |
| Ettercap не видит хостов | Проверь, что ты в той же подсети |
| GUI не запускается | Используй CLI: `sudo ettercap -T -M arp:remote /target1// /target2//` |
| Пароли не ловятся | HTTPS не снифается, нужен sslstrip |
| Kali зависает | Слишком много трафика, уменьши scope |

### CLI-режим (без GUI)

```bash
sudo ettercap -T -q -i eth0 -M arp:remote /192.168.56.30// /192.168.56.1//
```

Расшифровка:
- `-T` — текстовая консоль.
- `-q` — тихий режим.
- `-i eth0` — интерфейс.
- `-M arp:remote` — режим ARP-MITM.
- `/target1// /target2//` — жертва и шлюз.
